# Design system gaps (iOS)

Source of truth: https://claude.ai/artifact/4jeEJ91V5eRxpDn8NtqNgK, vendored at `design-system/` (version in `design-system/VERSION`).

This is the hand-off for design-system work. It has four parts:

- **A. Open gaps**: patterns the app needs that the DS does not define yet.
- **B. Spec contradictions**: places where the snapshot disagrees with itself, and the call taken for each.
- **C. Values with no token**: values the spec gives that have no token, and what iOS draws instead.
- **D. Resolved**: gaps that have closed, kept as history.

The rule when the spec disagrees with itself: the component README wins over older root-README prose and over `index.d.ts` / `api/`. `bundle.css` settles anything a README leaves out. A call that breaks this rule says why.

### Composites with an interim mode

- **PhotoStrip edit mode** (`Composites/PhotoStripEditor` + `Tile`, `Item`, `+Drafts`). It uses PhotoCard `sm` tiles. Remove is AppButton `secondary elevated` icon-only (the one 44pt size). The first tile carries a "Cover" Badge `elevated sm`; recipe pages are badged "Page N". "Camera" is an AppButton and "Library" a PhotosPicker with an AppButtonLabel. Reorder works through the context menu and accessibility actions (Make cover, Move left, Move right) rather than drag, which would fight the horizontal scroll. Recipe page photos cannot be reordered. `Composites/AssetPhotosPickerSection` is the shared wrapper: a DSSection ("Photos", trailing "Optional") over the editor, opening MediaViewerSheet on tap. **The DS should say** whether it wants drag-to-reorder.
- **ScreenHeader avatar edit mode** (`Layout/ScreenHeaderAvatarEdit` + `Composites/AvatarPhotoPicker`). Onboarding's profile step, your own Person profile and the Dinner party header (any member) make the `xl` avatar editable. The whole 80pt avatar is the button (press `opacity-70`), with a camera badge on its top-right: a `spacing-8` circle in AppButton `elevated` paint (`panel`, `text-primary`) lifted with `shadow-md`, its centre on the circle's edge at 45° (offset computed from the diameters, no new value), `camera` at `sans-xs` semibold, visual only. Tapping opens the native camera (`UIImagePickerController`, front camera) with a library button floating top-trailing over its controls (UIKit `glass` button, 44pt); that button closes the camera and opens Photos. With no camera it opens Photos directly. Remove photo lives in the avatar's long-press menu (and as an accessibility action), since the native camera has no room for it. A party's new photo becomes its cover (first in `photo_paths`, replacing the old cover when the party is full). Avatar also gained a local `photoData` preview and, with an empty `name`, draws a bare `primary-soft` circle instead of "?" (onboarding before the name is typed). **The DS should decide** the badge's size, glyph and placement; whether a sub-44pt visual is allowed when its target is the larger avatar; whether edit mode belongs on Avatar or on ScreenHeader; where Remove photo should live; the camera overlay's library button; and what an Avatar with no name shows.
- **ListRow inactive** (`ListRow.inactive()`). Someone invited to a party who hasn't joined sits at the end of every member list (PartyMembersSection, PartyMembersSheet, HouseholdMembersSection, PartySetupStepView, and PartyInviteView's "Invited" list) as `PartyInviteRow`: the lead, title and meta at `opacity-50` (`DS.Opacity.disabled`), while the one trailing control, "Remind" (`primary solid sm`, resends the invite), stays at full strength and tappable. Revoke moved from a second row button to the row's context menu, so the row has one button. This replaces ListRow README's Invite shape (Resend + Revoke) and the separate "Invited" section inside member lists. **The DS should decide** whether ListRow gets an `inactive` state, whether a dimmed row may carry a live control, and where Revoke belongs.
- **ListRow meta lines** (`ListRow.metaLines(_:)`). ListRow's meta is one clipped line. The Pro score sheet's reason rows (`TableReasonRow`) put a full sentence in it ("Astrid Lind and Joel Sanden scored it 20 above their usual"), which is the content, so they set `metaLines(nil)` and the meta wraps. **The DS should decide** whether meta may wrap, and if so whether that is a ListRow axis or a different row.
- **Sheet step toolbars**: `.sheetNextToolbar` (first step: close + "Next"), `.stepNextToolbar` (pushed middle step: back + "Next"; the rate-a-meal flow) and `.stepCommitToolbar` (pushed last step: checkmark or spinner, no interactive dismiss while saving). Optional steps put a full-width `secondary ghost` "Skip" pinned to the bottom (`RateStepView`); single-choice steps also advance a `duration-layout` beat after a pick. Every step reads its state from the sheet's `FormSession` (AGENTS.md §5B); `.stepCommitToolbar(session, title:)` can show a text action in place of the checkmark. **The DS should document** multi-step sheets.
- **"Discard changes" dismissal** (`.editorSheet` / `.discardGuard`, `Core/Extensions/View+EditorSheet.swift`, with `Foundations/SheetDismissAttemptObserver`). Edit sheets dismiss like Mail: untouched, swipe and close work freely; once changed, a swipe springs back and both swipe and close ask a native `confirmationDialog` "Discard changes?" ("Discard changes" destructive, "Keep editing" cancel); while saving nothing dismisses and the checkmark is a spinner. An unchanged edit's checkmark just closes. Read-only, picker and overview sheets always swipe away. The BottomSheet README covers one read-only sheet. **The DS should document** BottomSheet dismissal per sheet type, and the discard prompt's copy.

### Questions for the DS

- **ScreenHeader `centered`.** The README has no `align`, and only an avatar or the `tabRoot` / `moment` roles centre a header. `ScreenHeader` takes `centered: Bool` (default `false`) for a `standard` header that opens a sheet as a centred prompt (the New meal sheet with no recipe yet: title, sentence, Pick / Create recipe). An avatar always centres, whatever `centered` is. The DS should decide whether this is a role or a flag.
- **Avatar and Dynamic Type.** The circle is fixed, so initials can clip at accessibility sizes. Should Avatar scale?
- **Thumbnail in a row.** ListRow's photo lead is PhotoCard `xs` (80pt), so photo rows are about 96pt tall in a `spacing-14` row. Confirm.
- **Category cover crop.** LabeledPhotoCard `lg landscape` is 4:3, but "Imagery" says only 1:1 and 4:5 crops are safe. Confirm.
- **"Current row" state.** The recipe leaderboard can no longer mark the recipe it was opened from.
- **Field success state.** EmailInviteCard's "Invitation sent" sits in the hint slot with no colour.
- **ListRow meta.** There is one meta line and one ink, so meal notes, notification dates and the "Invitation resent" feedback lose their emphasis. The canvas tones "Waiting on 2" `warning-text` after the party name, so ListRow takes a `metaAccent` run (`ListRowMetaAccent`, default `warning-text`) joined with " · ".
- **Value step.** The README gives no type step for a ListRow `value` or a SegmentedBar inline figure. Both are `sans-sm` tabular.
- **Onboarding progress.** The Bar has no width in the navigation bar; it takes `spacing-20`.
- **AppButton `reaction solid`.** Neither README says how it looks ("A solid fill never carries text"). Only `soft` is used; `solid` inks `reaction-text` on the fill, as bundle.css does.
- **Semibold serif.** Only Newsreader Regular is bundled, so `weight: .semibold` has no effect on serif steps.
- **TextArea over `maxLength`.** The README doesn't say whether the hint turns `destructive-text`. Today only the border and the counter change.
- **Empty score.** No longer drawn: the unrated rater sheet shows only the person and the remind button (product call, 5 Oct 2026), and the meal's score card carries "No score yet". ScoreValue still has no empty-state glyph of its own.
- **Taste match verdicts.** The member sheet's Taste match ScoreCard shows a verdict word the DS doesn't define: Close (85+), Near (65–84), Apart (below 65). The DS should name these.
- **Labelled row buttons.** PendingPartyInvitesSection (Accept / Decline) follows the new ListRow rule; PartyInviteRow is one "Remind" plus Revoke in its context menu (see "ListRow inactive"). PartyMembersSheet's remove and SearchHistorySection's clear still use an icon-only ✕ and need labels.
- **PhotoStrip add tile title ink.** The README gives "'Add photo' `sans-sm` semibold" and no ink. It is drawn in `text-primary`.
- **Timeline rail.** bundle.css draws the 2px rail at `top: spacing-2.5` (centre 11), one point below the dot's centre (10). iOS centres the rail on the dot.
